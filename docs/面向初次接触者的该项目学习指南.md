# nexuscli 初次接触学习指南

这份指南面向第一次接触本项目的同学，目标是让你在 30 分钟内跑起项目、理解核心架构，并完成一次最小插件扩展。

## 1. 你会学到什么

- 如何在本地启动 nexuscli
- nexuscli 的核心目录结构和职责分层
- 插件机制如何工作（发现、校验、注册、隔离）
- 如何写并接入一个最小插件
- 常见问题的排查方法

## 2. 项目定位

nexuscli 是一个基于 Typer 的可扩展命令行工具，设计重点是：

- 可扩展：命令通过插件接入
- 可协作：多人可以并行开发不同插件
- 可治理：通过 Entry Points 标准化发布和加载
- 可恢复：单个插件失败不会拖垮整个 CLI

## 3. 目录速览（先建立全局认知）

```text
nexuscli/
  src/nexuscli/
    main.py                 # 入口：创建 app、加载插件、启动 CLI
    app.py                  # Typer 根应用
    config.py               # 配置读取与持久化
    runtime.py              # 本次调用的插件运行态信息
    core/
      plugin_contract.py    # 插件契约（必须遵守）
      errors.py             # 插件相关错误类型
    loaders/
      entrypoints_loader.py # Entry Points 插件发现
      folder_loader.py      # 本地目录插件发现（可选）
    plugins/
      manager.py            # 插件生命周期编排
      registry.py           # 命令挂载与冲突处理
      builtins.py           # 内置插件清单
    commands/
      plugin_admin.py       # plugin 命令组
      file_batch_rename.py  # file rename 命令
  docs/
  tests/
```

建议先按顺序阅读：`main.py -> manager.py -> registry.py -> plugin_contract.py`。

## 5. 运行时执行链路（理解一次调用发生了什么）

执行 `nexuscli` 时，会发生：

1. `main.py` 创建 Typer 根应用
2. 读取配置（`config.py`）
3. `PluginManager` 按顺序加载插件：内置 -> Entry Points -> 本地目录（可选）
4. 对每个插件做校验：版本、依赖、唯一 ID
5. `PluginRegistry` 挂载命令并处理冲突
6. CLI 开始接收并执行命令

要点：插件变更在“下一次调用”生效，而不是进程内热重载。

## 6. 插件机制核心概念

### 6.1 插件契约

每个插件都要实现 `CliPluginBase`，至少提供：

- `metadata`: 描述插件信息
- `typer_app`: 提供 Typer 子应用

### 6.2 元数据里最容易踩坑的字段

- `plugin_id` 必须全局唯一
- `command_name` 决定命令路径
- `min_cli_version` 必须是合法版本约束
- `dependencies` 建议写精确区间，避免运行时不兼容

### 6.3 冲突策略

- `error`：默认策略，冲突时报错并标记失败
- `skip`：冲突插件被跳过，CLI 继续运行

## 7. 第一个最小插件（学习型实践）

下面是最小实现思路：

1. 创建一个独立 Python 包
2. 写一个 `typer.Typer()` 子应用并定义命令
3. 实现 `CliPluginBase`
4. 在 `pyproject.toml` 里注册 Entry Points 到 `nexuscli.command`
5. `pip install -e .` 安装插件
6. 回到主项目执行 `plugin list` 验证插件已加载

你可以参考文档：

- `docs/plugin_developer_guide.md`

## 9. 常见问题与排查

### 9.1 插件没有出现在帮助里

按顺序检查：

1. Entry Points 组是否是 `nexuscli.command`
2. 插件是否已安装到当前 Python 环境
3. `plugin list --failed --skipped` 的输出原因
4. 是否被禁用（`plugin inspect <plugin_id>`）

### 9.2 插件加载失败

通常是：

- 版本不兼容（`min_cli_version`）
- 依赖缺失或版本不满足（`dependencies`）
- `plugin_id` 重复

### 9.3 批量重命名不执行

- 先看是否命中 pattern
- 检查冲突提示（目标已存在或多源映射同一目标）
- 先用 dry-run 调整规则，再 `--apply`

## 10. 推荐学习路径（给新人）

1. 第 1 天：跑通项目并读 `main.py` + `manager.py`
2. 第 2 天：读 `plugin_contract.py` + `registry.py`
3. 第 3 天：写一个 hello 插件并本地安装
4. 第 4 天：为插件补测试和发布说明

完成以上 4 步，你就能独立开发并发布 nexuscli 插件。
